# Brand Concierge概觀

Brand Concierge是一個代理平台，可讓企業和品牌在其面對客戶的介面上（網站、行動應用程式和其他數位屬性）啟動個人化的對話體驗。 每個對話都以品牌自己的內容和護欄為基礎，而整合可讓這些對話的深入見解流入品牌生態系統的其他部分，例如Marketo Engage。

## 主要元件

Brand Concierge部署有兩個主要部分：

| 片段 | 簡介 |
|---|---|
| **訪客體驗** | 品牌導向表面，例如網站或行動應用程式，訪客可在此與禮賓處互動並即時獲得回應。 |
| **撰寫者** | 此從業人員介面用於設計禮賓體驗，並管理禮賓、整合、設定、評估、部署和分析。 |

## 本指南中涵蓋的撰寫器模組

在Composer中，主要模組（以及本指南所涵蓋的範圍）為：

- 使用者管理（第3節）
- 知識來源的建立與管理，由服務人員共用（第4節）
- 禮賓管理：整合、技能、禮賓指示、語調和語音、視覺風格和聊天元件（第5節）
- 評估（第6節）
- 部署（第7節）
- 上線檢查清單（第8節）
- Analytics （第9節）

## 片段如何連線

會透過整合（連線）查詢知識來源（內容），也就是由技能（行為）呼叫，所有內容都包裝在訪客互動的禮賓處（整體體驗）中。

## 字彙表

這些詞語會顯示在Composer的整個介面中。

| 術語 | 定義 |
|---|---|
| **門房** | AI聊天體驗本身：每個品牌、網站或使用案例一個。 一個帳戶可以有數個帳戶。 |
| **撰寫者** | 用來建立和管理門房的介面，與網站訪客看到的不同。 |
| **知識來源** | 門房在回答問題時（例如網站頁面或產品清單）可使用的內容。 沒有禮賓服務，禮賓服務生就沒有什麼可回答的。 |
| **整合** | 與可擷取資訊（例如網站內容或即時產品目錄）的系統連線。 |
| **技能** | 禮賓人員可執行的特定功能，例如回答一般問題、比較產品或預約會議。 技能使用一或多個整合來執行其功能。 |
| **護欄** | 定義服務人員不應做什麼或討論的規則，例如競爭者或法律建議。 |
| **評估** | 包含樣本問題和預期答案的結構化測試，用於評估門房表現。 |
| **資料串流識別碼** | 技術識別碼，指定將訪客活動資料在Adobe系統內的傳送位置。 由IT或分析團隊提供。 |
| **沙箱** | 組織內的獨立工作區。 一個組織可以有多個門衛；每個門衛可以容納多個門衛。 |
| **IMS組織** | Adobe用於組織整體帳戶的辭彙。 |
| **MCP** （例如Commerce MCP） | 與特定系統（例如即時產品目錄）之間由Adobe管理的聯結器，使用IT或商務團隊提供的程式碼或金鑰進行設定。 |
| **CJA (Customer Journey Analytics)** | Adobe的分析產品。 Brand Concierge會自動在此處布建入門控制面板，而不需要其他設定。 |

>[!NOTE]
>
>行銷人員通常可以完全略過第3節&#x200B;*使用者與存取管理* （IT中的某人只完成一次），並從第4節&#x200B;*知識來源*&#x200B;開始。 只有在設定新隊友時，才會回到第3節。
