# 技能與整合架構 {#skills-and-integrations}

整合（先前稱為工具）是指與資料來源或後端的連線。 技能是一種行為。

一個整合可供許多技能使用。 一種技能可使用數種整合。 您可以個別設定這些變數，並將它們對應在一起。

## 技能

技能是門房的行為階層。 這是可重複使用的已命名單位，可定義服務人員可執行的單一工作：其處理內容、何時進入以及回應方式。 技能本身沒有資料；它會從附加至它的整合中借用功能。

每一項技能都由五個部分組成：

| 部分 | 簡介 |
| --- | --- |
| 名稱 | 技能的識別碼 |
| 說明 | 此技能的目的，簡單來說就是其目的 |
| 使用時機 | 觸發條件。 這是路由訊號，會告訴接聽人員何時叫用這項技能，而不是叫用其他技能 |
| 整合 | 此技能允許呼叫以執行其任務的特定工具。 技能只能使用此處附加的內容 |
| 指令檔 | 這些詳細指示管理技能的行為方式，以及技能如何解讀請求、格式化其回應和套用其護欄 |

技能在執行階段的行為：當使用者訊息到達時，平台會比對每個使用中技能的「使用時機」觸發條件，並將訊息路由至對應的技能。 然後，該技能會執行其指示，並僅呼叫其附加的整合。 其指示會與品牌設定檔和任何其他作用中技能一起組成禮賓員的整體執行階段行為。

技能決定要做什麼以及何時做。 它本身不會連線至任何資料；這是整合的角色。

## 整合

整合是門房的功能層。 這是與外部或後端系統（知識庫、內容來源、即時商務目錄）的連線，可實際擷取資料或執行動作。 如果技能是判斷，整合就是功能。

每項整合都有以下特性：

| 特性 | 其含義 |
| --- | --- |
| 連線和認證 | 整合使用自己的設定（例如商務環境ID和API金鑰）向其後端進行驗證。 此設定會將它指向正確的資料來源 |
| 公開的功能 | 整合可讓一或多個可呼叫功能可供使用，即技能可叫用的個別動作。 例如，Commerce MCP會將產品搜尋、產品詳細資訊、變體和Facet探索顯示為個別功能 |
| 可重複使用 | 一個整合可以附加到許多技能，相同的整合服務於許多門房和客戶。 此重複使用是架構的核心效率 |

整合在執行階段的運作方式：當技能觸發並決定需要資料時，會呼叫整合的工具之一。 整合會針對即時後端執行呼叫，並將結構化資料傳回技能，然後技能會使用這些資料來形成回應。

整合提供功能，但不作判斷。 它會等待技能呼叫、執行要求的特定工作並傳回結果。

### 功能與限制（自助服務範圍）

- **自助服務，無工程：**&#x200B;編輯指示、編輯「使用時機」觸發器、附加或分離現有整合、啟用或停用技能，以及連線支援的整合（例如，使用有效憑證的Commerce MCP）。

- **不是自助式，需要工程：**&#x200B;建立目錄中沒有的全新工具或聯結器、新增框架不支援的護欄類別，或變更後端公開的資料。

- **兩個技能之間觸發重疊是設定風險：**&#x200B;如果兩個技能可能確實在相同的郵件中引發，路由可能會不一致。 寫入觸發程式以避免真正的歧義，而不是依賴路由器來解決它。

## 建立禮賓時的有線內容

透過一鍵設定建立服務生時，會為您組裝基準線。

| 建立時連線 | 詳細資料 |
| --- | --- |
| 知識庫（資料） | 早期抓取會從透過網站地圖找到的網站前10到15頁建立知識庫。 這是內容存放區，而非技能或整合 |
| 知識庫搜尋（整合） | 內建整合，連線至抓取的知識庫，並用來進行搜尋。 抓取不會建立此內容；它會指向抓取產生的內容 |
| 網站諮詢（技能） | 在基準線中啟用，連線至呼叫知識庫搜尋，以查詢抓取的知識庫 |

## 常見問題集

**技能與整合之間有何差異？**

整合是指與資料來源或後端的連線，是服務人員可觸及的目標，例如知識庫或即時商務目錄。 技能是一種行為；它決定門房該做什麼、何時做，以及允許使用哪些整合。

**經驗法則：**&#x200B;整合是一項功能；技能是判斷何時及如何使用該功能。

**同一整合是否可由多個技能使用？**

是的，這是刻意為之。 「目錄探索」和「產品比較」會共用Commerce MCP的工具。 一次建置整合，並在許多技能和許多客戶中重複使用，是2.0架構的核心效率；這是移除每個客戶自訂組建的原因。

**從業者是否可以在沒有工程的情況下新增全新的功能？**

僅當其整合已存在於目錄中時。 從業人員可自由對映、設定及指示任何現有的整合；亦即自助服務。 但是，如果功能需要尚不存在的後端或聯結器（新API或新資料來源型別），則需先建置整合的工程任務。 一旦將其存在於目錄中，再次將其設定為自助服務。

**這與BC 1.0的單一系統提示有何不同？**

在1.0中，行為是由一個大型系統提示（資訊清單）驅動，這很難安全編輯，通常需要工程變更。 在2.0中，資訊清單仍然存在，但是由模組化片段所組成，而非寫入為一個區塊。 這就是讓從業人員能夠設定行為，並使個別護欄和指示清晰可稽核而不是隱藏在提示中的原因。

**提前抓取會建立什麼內容？**

此抓取會建立知識庫，這是網站內容的可搜尋存放區，可透過網站地圖從前10到15頁建立。 這僅是資料層。 抓取不會建立技能或整合；而是產生他們稍後動作的內容。

**如果抓取建立知識庫，則什麼是知識庫搜尋整合？**

「知識庫搜尋」是內建的整合，其工作就是搜尋該知識庫。 知識庫就是資料；知識庫搜尋是查詢它的功能。 它們是兩個不同的專案：一個是內容，另一個是讀取內容的工具。 將兩者視為相同是很常見的錯誤；但事實並非如此。

**服務生如何在建立時回答一般問題？端對端？**

三個圖層會依序運作，並準確地對應至技能、整合和資料模型：

- 提早抓取會從網站的頁面（資料）建立知識庫。
- 內建的知識庫搜尋整合功能會搜尋該知識庫（整合功能）。
- 「網站諮詢」技能用於呼叫知識庫搜尋（行為）。
